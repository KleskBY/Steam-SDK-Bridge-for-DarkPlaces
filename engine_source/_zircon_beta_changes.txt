// zircon_dpbeta_changes.txt - October 14 2023, November 12 2023

Zircon is DarkPlaces with a mouse-driven menu, ALT-ENTER fullscreen/windowed switch,
cut/copy/paste in console and enhancements mostly focusing on user-interface.

// Zircon Beta Release 106

1. Menu QC now supports drawing the loading screen (m_drawloading) from Wrath: Ruin of Aeon

   (This implementation extends the Wrath implementation to provide a little more flexibility.

	Usage: float m_drawloading(vector video_mode_size, float is_opaque)
    1. video_mode_size is the current video mode size like 1920 x 1080
	2. is_opaque always has a value of 1.
	Return value:
	Return DRAW_OVER_LOADINGSCREEN_0 to draw over the standard loading screen.
	Return DRAW_NO_LOADINGSCREEN_1 to draw instead of the standard loading screen.

	Advanced: On loading the Menu QC, with "developer 1" or "zircon.exe -developer" command line ..
    will print to console "Detected m_drawloading"

2. Menu QC now supports drawing save games as pictures.  Zircon Beta has put screenshots in save games since
   Release #43 (Quakespasm and DarkPlaces ignore the screenshot data and load the saves like normal) 
   
   Now precache_pic ("mysave.sav") loads the picture in the save game

   precache_pic ("mysave.sav");
   drawpic ('100 100', "mysave.sav", '512 320', white_111, alpha_1_0, DRAWFLAG_NORMAL_0);
   This would work in CSQC as well.

   Advanced: precache_pic returns NULL if it cannot load a picture (NULL is the same as "world" .. both of which are just fancy zeroes)

   So this would work ... if (!precache_pic("mysave.sav")) // couldn't load save pic

3. "mset", "medict" and "medicts" commands for menu entity listing, examination, editing.

4. "prvm_functions server" prints all the known function in the progs.dat ("prvm_functions client" would do CSQC, etc.).

5. "prvm_builtins_in_prog server" prints all the builtin functions (like drawpic or strlen) used in a progs.dat

6. "prvm_builtins server <optional required string>" prints all QuakeC builtin functions.
   "prvm_builtins client draw" prints all CSQC with the word draw in the name.  Related: documentation_dump

7. "edicts nearby" .. lists entities near you and in front you.  "edicts nearby 200"  lists entities 
   near you at a radius of 200. "csedicts nearby" does it for CSQC entities.

8. "constants modelflags" now available.  The constants command prints engine constants like "constants effects".
   The constants command autocompletes so press CTRL + SPACE or TAB to cycle through the known tables.  The purpose
   of the constants command is to expose engine known constants. (TODO: Make edict command atomize the field?)

	Advanced: The modelflags field can give an entity the ability to rotate like self.modelflags = MF_ROTATE_8 would
    make a model rotate like a ground weapon (can also give trails).

9. Tweaked total conversion support -- QUALKER and OBJECT N builds no longer try to load Quake.kpf (Quake Remaster)
   and also do not try print messages about "shareware" or "registered version".

10..MAP Pre-Processor ... Adjusted "_clone_classname" .map pre-processor to handle brush models and added a "origin_x" 
    and "origin_y" adjust command.  I use this to have braziers have automatic light sources and automatic CSQC 
	particle emitters with both the light and the emitter having a slightly offset origin .. during .map compile.

11. Fixed the Menu QC "cin_open" command (it was broken in DarkPlaces Beta, but video playing via playvideo is also
    broken in DarkPlaces Beta but has long been fixed in Zircon Beta).  However, "cin_open" playing a video fullscreen
	is less helpful for menus than I thought .. even Blood Omnicide does not use "cin_open" and most of the video
	code seemed to be written by Vortex.  Anyway, it works now.

    Sidenote: What I will be doing instead ... if I want an animation, I will be likely using a Q3 shader like "AnimMap" which
	can do 64 frames of animation and render in 2D.  It is possible I revisit this in the future, the strength of the
	video playback implementation is that it only uses a single texture and continually updates the texture (GL upload).

	For most purposes, demo playback or an animated texture is a better tool for the job.

12.	Fixed a very minor order insertion issue with Zircon Beta automatic creation of a default "+zoom" alias.
	It is supposed to allow a mod to override the alias, just like DarkPlaces "alias startmap_sp "map start"" can
	be overrriden.  But due to insertion order, the mod override was not occurring.  Few mods have
	an alias named +zoom and likely no traditional Quake single player mods do -- so unlikely anything was affected.
   
	However, I have a mod that uses +zoom with a specific weapon to show a sniper view and it didn't work because
	the engine override the alias instead of the mod overriding the engine alias.

13. Zircon Beta nows sets the "SDL_WINDOWS_DPI_AWARENESS" hint on Windows.
	Zircon Beta has told Windows "no dpi awareness" in every version at the application level, so this probably does
	absolutely nothing differently, but wanted to add the actual code that tells SDL that.

FUTURE: CTRL-I in console to display parameter arguments?

// Zircon Beta Release 103

1. Fixed loadfont autocompletion.

2. Pre-processor support: For fake brush model collision bodies to effectively get non-cubeoid collisions
   with .md3 and such.  Example: "_collision_body_9" "models/vehicles/psx/van_car04.md3 188.9375 101.8125 82.25"
   in world model.  They are made of common/caulk and common/origin textures and at the center of the
   world.   In console: "csgtool maps/mymap.map collision_body" also works -- the csgtool command invokes
   the Zircon .map pre-processor at will in the console.

3. r_shadow_q3_radius_fade_hack - specify the fadescale to use for Q3 "radius" lights (spotlights) when DarkPlaces
   real-time lighting is enabled.  Imperfect, but can decrease super-bright real-time lights for Q3 "radius"
   light entities that DarkPlaces doesn't understand.

4. "tosses_speed" (default: 1000) "tosses_keep_fields" (defaults to "classname,origin,angles")
   For use with "ent_create_toss" and "ent_create"

   "tosses" command lists entities created by the above.  ("ent_remove" removes from list).

5.  "sv_movetype_follow_csqc_sendflags 6" will make server-side CSQC entities with MOVETYPE_FOLLOW that
    have moved will get .SendFlags set to 6 (default is 0x00FFFFFF .. all flags).  This allows mods to
	do less than a full update for moved entities (for instance, only send the origin and angles instead
    of sending all fields).

// Zircon Beta Release 101

1. "ZIRCON_GETSURFACENUMPOINTS_FLAGS" - getsurfacenumpoint now fills 
	trace_dphitcontents, trace_dphitq3surfaceflags for the surface.

2. CSQC entity for world gets modelindex field set to 1 when CSQC_Init occurs.  This causes
   getsurfacenumpoints function to work on the world model.  This is effectively a DarkPlaces bug-fix for
   a set of functions that -- while useful -- have not been commonly used in the past because they are 
   for very specific purposes.

3. "constants" command that prints constant tables to the console.  Example: "constants movetype".
   Particularly helpful for less commonly used DarkPlaces constants like "contentflags_dp" or
   "surfaceflags" -- this autocompletes (CTRL+SPACE) various constant tables.

4. "autocvars_from_clipboard" .. extracts the autocvars from QuakeC code on the clipboard and sorts it to
   a list and prints registration commands to the console.  For serious CSQC development.

5. .map pre-processor bug-fix of metrics calculation after the first Q3 patch is encountered (code mistake).

6. "vectornormal3" console command prints more information.

7. "bitatomize" can take a 3rd argument specifying constant type and only prints non-zero bits.

8. "eset" command now autocompletes the entity number that you are looking at (providing it is solid can
   be hit by a traceline).  Invisible entities, SOLID_NOT and translucent surfaces (glass or fence textures) will 
   not collide with the type of traceline performed so be sure to look at a solid part of an object.

9. Source code: There is a disabled block of text to change the lavaball effect from MF_ROCKET to EF_STARDUST
   on load of the alias model.

10. csgtool maps/mymap.map infodump now prints size information for all entities and brushes in the .map

11. "showangles 2" will show the current normalized view vector (v_forward in QuakeC).
    "showtex -1" will show the current distance to texture collided against -- if tool_marker is enabled
	it will mark that location.  This is like a measuring stick indicating where the collision occurred.

12. mod_q3bsp_lightgrid_texture now defaults to 0 (it defaults to 1 in DarkPlaces Beta and does not exist at all
    in DarkPlaces Classic).  The default of 1 makes Quake monsters and other models look wrong in Quake 3 maps
	and since this does not even exist in DarkPlaces Classic which is what Quake 1.5 and Xonotic use -- I don't
	know of anything that really desires this new behavior.

13. A test cvar named r_glsl_baker_test to alter the light direction by the view yaw value.

14. "csgtool maps/mymap.map _csg_test_rewrite" will read and re-output the .map as is.  This
    is a test tool to verify it writes what it reads.  (Note: it appears J.A.C.K. and possibly
	other tools read patch values as doubles not 32-bit floats).	

15. "reflectcubemap" set the default cubemap for _reflect textures.  Ideally -- like usage in
    a mod -- the texture name should only be used for this purpose and should not be a texture 
	that might be used with any in-game textures (because then it would be possible for the texture
	to get loaded and then later unloaded).  TODO: hardcode exclusivity.

16. r_lavaball_hack 1 -- on model load, causes lavaball.mdl to get EF_FLAME as the trail
    instead of TR_ROCKET.  This allows lavaballs to have a different effect than rocket trails.
	For best results, need an effectinfo.txt and particlefont.tga 
	(see https://www.moddb.com/mods/zircon-engine/downloads/csqc-rain-snow-lava-smoke for a good
    example -- CSQC Rain / Snow / Lava Smoke .. and copy/look at effectinfo.txt and the 
	particles/particlefont.tga)

	NOTE: r_lavaball_hack 1 takes effect when a model is loaded.  Type "purgeall" in the console to 
    force all models to reload.

// Zircon Beta Release 100

1. MOVETYPE_FOLLOW CSQC entities on the server now update origin/angles.
   (Server entities with .SendEntity function get .SendFlags set ALL FLAGS (0xFFFFFF) if origin or 
   angles change during the physics frame.)

2. "Decal DropToFloor Automatic" Support for Q3MAP when Zircon is used as CSG .map pre-processor (-csg)
   "_decal" "target" "_automatic_droptofloor" support (Q3 .map format).  Allowing decals in a map editor 
   to not need an "info_target" entity (they are automatically created if Zircon is used as a CSG phase tool -- the
   Zircon .map pre-processor.

3. New: "orientation upright" effectinfo.txt option, renders the particle as seen (billboard reverses, upside down)

4. "cl_particles_stain_mix_with_particle_color 1" cvar.  Set to 0 it mix the particle color with the 
   stain color and will simply use the supplied stain color only.

5. Support for a 2nd particle texture.  particles fade when "alpha" hits 0 or "time" elapses, make sure the
   first particle1 lives as long as or longer than the particle2 or the behavior is undefined.
   Supports: tex2, blend2, color2, tex2, size2, sizeincrease2, alpha2, time2.  FOR BEST RESULTS: don't mix
   (blend invmod) with (blend add or blend alpha) due to rendering batching.  Some behaviors with pt_snow
   are "undefined" -- like if the parent particle has a shorter lifespan than the child particle.

6. "particles_split" -- turns particles/particlefont.tga into up to 256 separate images 
   ("particles_join" will recreate the particles/particlefont.tga") now loads the first image to 
   determine size, and now writes .tga instead of .png.

   Note that the TGA export does not support compression.  To shrink particles/particlefont.tga with
   compression, open the TGA in specifically GIMP and re-save.  I say GIMP because many image editors
   mess up writing TGA (even applications like IrFanView) and GIMP is known to follow the exact
   specification.  The reason this specification matters is that Quake 3 and Quake 3 tools like map
   compilers also follow the exact specification and it is important that the map compile pipeline
   has a proper .TGA.  (And DarkPlaces has always required proper TGAs due to various Quake tool pipelines).

7. Simplication of the console autocomplete system.  More things autocomplete and better.  Additionally,
   csqc_progname autocompletes.

8. Fixed "dec" without a value defaulted to positive 1 instead of negative 1.

9. Fixed a bug where a memory pool wasn't allocated for CSQC modelview project.  Affected the
   "CSQC modelviewer" prototype released earlier in the year.

10. ent_create now says the entity number and the origin. (autocompletes)
11. ent_create_copy <entnum> command.  Like ent_create, uses traceline collision location as origin.
12. ent_create_trace_fraction cvar defaults to 0.8 to move ent_create positon back from the wall.

13. bitatomize now does 40 bits and changed to print 64 bit integer representations.

14. bind a +(press TAB) now autocompletes correctly instead of autocompleting the current value.

15. OBJECTN builds now use correct Window icon (like QUALKER).

16. "cd info" correction (it didn't work before due to a typo)

17. "jpegresample" to resize a folder of png and tga into jpg of specified size (intended for resizing video
   frames, generating an alpha channel if specified (and copying shader text to clipboard for creating a q3 
   animated texture).  Any non-zero value of "cl_video_frame_modulo" will skip images (2 will skip 50%, 4 will
   skip %75, 5 will skip 80%  ... uses index % (modulo) 4 != 0 (where 4 is cl_video_frame_modulo value)   
   to skip images (to thin out, say, 1000 video frames to 200.

18. "png_texture_suppress 1" to not load png textures during map load.  Special case for testing
   automatically generated jpeg animated textures.

19. Support for Q3 shader "animclampmap"

20. cl_video_frame_modulo cvar also affects "playvideo myvid_25_fps" where quake\id1\video\myvid_25_fps is a folder
   of .jpg images with names like 00001.jpg, 00002.jpg causing jpeg stream playback to skip images.

21. "documentation_dump" dumps cvars, their default values and description to file (it says the file name it
   creates.

// Zircon Beta Release 98

1. "external_vis 1" supports loading external .vis files that give the original Quake maps
   transparent water.  The .vis files or the .pak or .pk3 must be in the same folder as
   the maps they are for.  This is so, say, the Travail start map does not try to load start.vis
   which would have invalid data.

2. Coronas without real-time light feature now is a cvar that defaults off because it can look
   wrong in Quake 1.5 which if you kill 50 monsters might create a few super huge coronas that
   otherwise would not normally render.  To turn on the "coronas without real-time light" feature
   now requires "cl_coronas_without_light 1" in the default.cfg of a supporting mod.

3. Hardcoded Quake 1.5 double barrel shotgun to have the EF_SELECTABLE model flag stripped so 
   it is not semi-transparent.  This conflicts with the Quakespasm MF_FENCE model flag, which
   Zircon supports.

// Zircon Beta Release 97

1. "map" command with no parameters prints the size of the map in MB.
   If a .map file is detected, calculates the compile time required.
   For instance, if you compile a .map in J.A.C.K. and Zircon starts you can type "map" and it might say

	filesize       30.4 MB
	compile time   6 minutes 14 seconds (374 seconds)

2. skybox autocompletion ("sky" command) changes skybox in real-time to allow fast on-the-fly trying skyboxes.

3. Fixed a minor missing .jpeg implementation (not .jpg) oversight that affected nothing (because it 
   would mess up mess up attempts to save a .jpeg, which the engine never did but a new feature does that).

4. "jpegcheck textures/ambientcg" - will check all jpg and jpeg in the folder texture/ambientcg
   and then print a list of them where the jpg or jpeg texture is "too big" and a 100,000 KB or more
   difference could be saved.  "jpegcheck textures/ambientcg go" will actually save these smaller images
   with "_newb" appended to the end of the filename so that "brick006.jpg" is written as "brick006.jpg_newb".

   (You can them look as these in an image editor and delete the old one and rename the new one, 
   I do not like the idea of the engine overwriting existing files so therefore it does not.)

5. Map dates in the maps menu works again.

6. shaderprint autocompletion pressing CTRL + SPACE (autocomplete from nothing) fills currently looked at texture.

7. con_textsize lower bounds limited to 2 with CTRL - (special characters or color codes can still affect it).

8. "maze_gen", "maze_to_map" automatic maze generation.  Work in progress.

9. .map pre-processor: "_heightmap" automatic alpha blending capability "_heightmap" "0 to 384"

10. Support for "mult" shader Blendfunc ("multiplicative" ==> GL_ZERO GL_ONE_MINUS_SRC_COLOR)

11. Support for numerous new .map pre-preprocessor capabilities and a console command "csgtool" that can
    run some of them.  (Many require using Zircon as a CSG stage tool in a .map editor giving Zircon the -csg
	command line parameter).

	These only work with the Valve 220 J.A.C.K. Q3 map format, known to be the best Q3 .map format and it is
	supported in TrenchBroom I believe.

	csgtool maps/mymap.map weld // Will combine adjacent triangles into rects ONLY for brushes
	// Only combines triangles for triangular brushes where the upfacing texture is the most common texture
	// in the .map.  It will then takes the rects created and tries to combine most of them in the rows.
	// RESULT: This heavily reduces the numbers of brushes in a terrain map.
	// RESULT: Your map editor editor will love you for having a 90% reduction in the number of triangles
	//         it needs to draw.  Probably speeds up map compile too.

	csgtool maps/mymap.map infodump // Prints textures used and frequency and other information.	

11. Fixed "pak_this_map" to work with filesystem upgrade from a few versions ago (meaning "pak_this_map" was broke).

// Zircon Beta Release 93

1. "Malice Fix" Added and defaulted to 1: "r_cull_darkplaces_classic 1"
	Malice bad model culling issue in first cutscene demo with a robot bossman with a cigar.
	It also will allow seeing monsters when noclipping outside the level, like DarkPlaces Classic did.
	LightningHunter had requested this behavior be restored a few months ago (at least as an option) and
	at the time, I was not able to determine where/how the difference was.

	"r_cull_darkplaces_classic 0" uses DarkPlaces Beta model culling and the Malice robotman doesn't always
	draw during the first cutscene (that logic determines, I am assuming, that he crosses the viewplane
	of the camera and shouldn't be drawn).

2. Windows Unicode Path support greatly improved.  Previously, the engine would run largely
   ok in a folder with Russian language characters, but some Zircon functionality like
   "folder" would fail.

3. "utf8_enable 1" now renders the menu correctly (menu sliders).  This enables unicode and is 
   utf8 is not compatible with the Quake character set and is meant for total conversion usage 
   like Q.U.A.L.K.E.R or Xonotic.  For example, the bronzed text in Quake is not ASCII (0-127 charcodes)
   and it gets the unicode treatment with utf8_enable 1 and does not draw because the characters have
   no drawpic for those characters.

4. Multiplayer => New Game was going to the server list menu.  Corrected.

5. Codebase: Eliminated numerous GCC warnings during Linux compile.  Many GCC warnings relate
   to coding practices in some ways and these almost all fit into that category.  For instance, GCC
   warns if a variable declaration hides a global variable of the same name or a previously
   declared variable of the same name (like if a new declaration is declared in a for loop).

6. Blocked portal generation for BSP model health and ammo boxes by adding a radius check of 128.
   Non-world (i.e. the real map).  The radius check was the most convenient way to block it -- it is
   already blocked in most instances, but connecting to a Quakeworld server was still triggering it
   because models precaching works in a different order.

7. Implemented Hemebond effectinfo.txt lightradius fix that allows lightradius for particles
   to work without also setting lightradiusfade.  This relates to effectinfo particle effects.

8. "pak_this_map" now adds .jpeg extension files.

	("pak_this_map" will take the currently loaded q3 format map and locate required textures, shaders and sounds
   and put them in a single folder and make a .pk3 in that folder.)

9. "opendialog" test command will open a file dialog on Windows only.  This is blocking.  
	Quake will stop cold while the dialog is active.  This is a test intended to pave the way for 
	utility commands via the console.

10. Addressed several "silent disconnect" scenarios.  Like host errors, playdemo and it can't find the 
    file.  These would cause the console to not render instead be pitch black because it cl_screen.c
	thought it was between startdemos.  Short version: Fixed.

11. "cliptraceoutline" will take the current image on the clipboard (like a PNG) and then generate
    an edge trace and put that image on the clipboard.  This is an intermediate for PNG to .MAP.

12. _layout_to_bbox .MAP pre-processor command written.  Perfection remains ...


// Zircon Beta Release 92

1. Give support giving keys.  Type "give" in the console and it will say what the options are.

	give autocompletes better and now can give or remove silver and gold keys.
   
   "give key_silver" when you already have one will remove it.

2. (MAPPING, Q3MAP mostly) Support for .jpeg extension to hide _gloss and _norm textures from J.A.C.K.  Probably
    works to hide textures from other map editors like Trenchbroom too.

3.  Set model lighting to white color for players, monsters, viewweapon with minimum lighting by cvar.

    model light control for monsters, players, view weapon
    
	r_modellight_players_nocolor // Set this to 1, player is never affected by color light
	r_modellight_monsters_noccolor // Set this to 1, monster is never affected by color light
	r_modellight_viewmodels_nocolor // Set this to 1, viewmodel is never affected by color light
	r_modellight_players_nocolor_minlight // Minimum lighting pct where 1.0 = fullbright and 0.0 = full dark
	r_modellight_monsters_noccolor_minlight // A good value is 0.5 or 0.4 to prevent gun from going full dark
	r_modellight_viewmodels_nocolor_minlight

4. "play" autocompletion improved.

5. con_savehistory cvar.  Some anti-virus complain about history.txt files.  Setting "con_savehistory 0"
   won't write the history to file and should avoid this anti-virus warning.

6. "traceline" command from 1000 distance to 16384 distance.  Prints distance to console.

7. CTRL + SPACE (autocomplete from nothing) vs. TAB autocomplete is now treated differently for:
   eset, cset, prvm_edictset, prvm_edictget

   Autocomplete will do verbose for CTRL + SPACE and non-verbose for TAB.

   For these commands, verbose says the field number and datatype.

8. "effects" is now bit-atomized for the "edict" command.  For example it will say "effects" 5 (1 + 4)
   This helps when the effects field contains multiple bits set. dphitcontentsmask is also bit atomized.
   And effects prints enumeration long values.

9. effectinfo_particleeffectnum TE_BLOOD will look up the effectname and get the current particle effect number.
   Particle effect numbers are very sensitive except for the Quake builtin ones and can change if an effectinfo.txt
   is edited.  Nonetheless, self.traileffectnum uses that and this new command will allow quick testing of
   effects as trails.  For example, "eset 29 traileffectnum 15" will set edict #29 to have traileffectnum 15.

10. (Q3MAP) "copy image" will copy an image to the clipboard for the current texture looked at. (Windows only)
    This only works for TGA, PNG or JPEG images.  So the Quake start map without replacements textures
	this does not copy the texture at this time.

11. (Q3MAP Shader): framemap1 - $map specifies frame0  then framemap1 specifies additional frames
   Resolves issue with q3map2 not knowing what framemap is and therefore incorrectly sizing the texture.
   This method allows any q3map2 compiler to be used.

12. (Q3MAP) pak_this_map would duplicate textures used as-is and textures found in shaders if they were the
    same shader and write them to the .pk3.  It now runs a uniqueness sort to filter out duplicates.

13. (ZIRCON.EXE as CSG Map Pre-Processor) Map preprocessor can now rename entities with world key "_rename" .
	Example: "_rename" "misc_model_torch=misc_model,misc_mdl_entity_kickable=misc_mdl_entity"
	Zircon.exe as a map preprocessor will rename all entity classnames of misc_model_torch to misc_model
	then rename all misc_mdl_entity_kickable to misc_mdl_entity before map compilation.

14. Fixed an autocompletion logic error that referenced an uninitialized variable in unusual cases.

15. Added more helpful description to v_cshift command.

16. Zircon Galaxy and id1 can exist in same gamedir, Galaxy can gamedir change into id1 and back with some 
    cvar reset difficulty.

// Zircon Beta Release 91

1. Removed sv_progfields cvar.  Obsolete.

2. "pos" command now updates _ang variable (the value can be used by using $_ang as $ converts a cvar to its value.

3. "pos silent" -- adding "silent" parameter to suppress all printing and copying to clipboard to allow a
   macro to print data to the console by pressing a key.

	Example: 

   bind q "pos silent; echo camera_origin:'$_pos' camera_angles:'$_ang' camera_interval:1"

4. Console editing: CTRL + left or right arrow now stops at periods.

4. Equation calculator.  "eq 2 + 2" or "eq floor(2+cos(1) ) + sqrt(2)"

   Type "eq" in the console and it says the details.  "pow" is an exponent operator so
   "2 pow 3 = 8".  Can't use "^" because C and QuakeC (and C style languages) use that for "xor".

   All values treated as double (64-bit floating point).  
   
   Equations are processed as standard "C" order of operator precedence.  QuakeC operator precedence is very 
   similar to standard C.

	Bitwise operators "&" (AND), "^" (XOR), "|" (OR), "<<" and ">>" and "~" (NOT) convert values to 
	signed 32-bit integer (int32_t) before performing the operation and the result is converted back 
	to double.

	This should be very similar to what QuakeC does in allowing floats (everything is a float in QuakeC)
	and looking at DarkPlaces opcodes for QuakeC, it looks like floats are accessed as int32_t
	for bitwise operations (using a union).

    "%" modulus operator is deliberately like QuakeC (4.1 % 4 == 0.1 not like zero like C).
	So "%" is basically "fmod()".
       
	Logical operators && and || are short-circuiting like in C.  (QuakeC does not do short-circuiting
	for && or ||).

    Division is as in QuakeC -- it is "double division"  10/3 = 3.3333 not C integer division where

1. Client-side prediction now blocks against monsters (cl_movement_collide_models 1) -- you don't want to walk
   through monsters, feels wrong and this is normal behavior for DarkPlaces and Quakeworld.
   
   (What happens is that the server will correct your movement saying "no you didn't move that far", but
   depending on the ping -- it can feel weird!) 

	Server is DarkPlaces, the player will collide against MOVETYPE_STEP / RENDER_STEP entities (no collision vs. scrags).
	Server is Quakeworld, the player will collide against monsters hardcoded into the engine (the Quaekworld tradition).
	
	Server is Zircon, the player will collide against entities model bounding box
	  IF entity is NOT marked "SOLID_NOT".  (Or SOLID_TRIGGER or SOLID_CORPSE).

	This data is transmitted via the RENDER_SOLID_NOT_BAKER_256 flag 
	(funky name is so it can be found in source code).
	
	This means Zircon client to Zircon server clientside prediction collides based on the QuakeC solid flag.
	Except that Zircon client does not know collision boxes set in QuakeC setsize that differ from
	the model bounding box.
	
	Mods that use (sv_gameplayfix_setmodelrealbox 1) and do not setsize on models, the collision size should
	be identical.  DarkPlaces with standard Quake does not use sv_gameplayfix_setmodelrealbox.
	
	Short version:  The Zircon to Zircon clientside collision is better, Zircon to Quakeworld coop collision
	is better than Quakeworld's and Zircon to DarkPlaces collision is better than DarkPlaces (which doesn't 
	collide against monster AND falsely collides against func_illusionary map models).

    Q3 Shader Reference

    tcMod scale <sScale> <tScale>
    Resizes (enlarges or shrinks) the texture coordinates bymultiplying them against the given factors of <sScale> and <tScale).
    The values "s" and "t"conform to the "x" and "y" values (respectively) as they are found in the original texture TGA. 
    The values for sScale and tScale are NOT normalized. This means that a value greater than 1.0 will increase the size of 
    thetexture. A positive value less than one will reduce the texture to a fraction of its size and 
    cause it to repeat within the same area as the original texture (Note: see clampTexCoords for ways to control this).;
